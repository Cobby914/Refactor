# ScaleSense co-simulation refactor roadmap

Each increment adds or checks one behavior against the legacy revision `98a4744`. Keep the existing CLI and GUI usable while bringing up a separate v2 path. Record evidence in [Progress](PROGRESS.md) and update architectural decisions as the implementation changes.

| Step | Deliverable | Acceptance check |
| --- | --- | --- |
| 1. Audit and ordered step controller | Inventory tick sites, trace lifecycle, compare the seven references and implement a standalone scheduler. | Unit tests prove SUMO → mirror → CARLA order, accurate step identity, and a terminal failure on discontinuities or partial steps. Record available legacy baseline measurements. |
| 2. Live adapters and lifecycle | Completed the traffic clock check with a managed SUMO child and an isolated CARLA endpoint. | Live CARLA and SUMO advanced at one effective delta. Tests exercised failed startup, interruption and repeat runs on the same CARLA world, checking settings restoration and child exit. |
| 3. Actor registry, transforms and traffic lights | Completed v2 traffic-only runs with the existing scenario controllers and map rules, acknowledged actor commands, scoped cleanup and ten mapped corridor heads. | Live runs exercised car, bike and walker movement, cull and re-entry, arrival and lost-response cleanup, and signal verification through a phase change. Two S08 processes matched sampled actor identities, blueprints and transforms with the same SUMO seed. |
| 4. Frame joins and legacy exports | Completed opt-in v2 single-run capture with bounded frame joins, exact ground truth, legacy exports and a sensor coverage manifest. | Unit tests exercised delivery order, duplicates, expiry and shutdown. Live runs verified all four radar layouts. A 600-frame capture passed the legacy labeler, Doppler/RCS processing and PointNet frame building. |
| 5. Campaign and GUI integration | Completed opt-in v2 CLI and GUI integration. Each campaign shares one rig and uses confirmed paired frames for warm-up and recording. | Two consecutive two-row campaigns produced exact recorded ranges and labeled segments. GUI Stop and a CLI SIGINT kept the confirmed prefix. An injected clock timeout ended the run and a retry succeeded. Live checks verified resource cleanup. |
| 6. Parity and performance | Completed the [matched live benchmark](BENCHMARK.md) across all four radar counts with two trials per engine and controls at `98a4744`. | Both paths saved the expected sensor frames. V2 paired all steps and cleaned up its rig. V2 took longer to record each window and its writer queue repeatedly filled. |
| 7. Recording throughput | [Parallelized camera PNG encoding](BENCHMARK.md#parallel-png-follow-up) with bounded pending work and ordered frame commits. | Recording wall time fell across all four radar counts. The 60-second, 14-radar default-budget run kept every paired frame and still took longer than real time. Legacy remains the default. |
| 8. Full-rate radar CSV throughput | [Batched v2 radar output by scan](BENCHMARK.md#batched-radar-csv-follow-up) with the existing CSV schema and precision. | The 60-second default-budget run kept all 1,200 paired frames and took 40.04 wall seconds. Same-scan CSV output matched the existing writer across all four layouts. An 80-frame full-rate excerpt passed the downstream dataset pipeline. |
| 9. Repeated full-rate campaigns | [Validated two consecutive three-row campaigns](BENCHMARK.md#repeated-full-rate-campaigns) at 14 radars and 15,000 rays/s per radar. | Both runs saved all 3,600 paired frames with exact segment ranges and restored CARLA. A Stop during the second row preserved the capture prefix and allowed a retry. An excerpt from all three scenarios passed downstream processing. |
| 10. Default engine rollout | Promoted v2 for standard 20 Hz single runs and new GUI campaigns. Saved engine choices, older plans without an engine, and implicit legacy selection for custom single-run rates or Traffic Manager ports are preserved. | The CLI and GUI selected the expected engine, both legacy launch paths ran, and a new v2 campaign recorded all 1,100 expected paired frames across 11 scenarios. [Rollout verification](PROGRESS.md#2026-11-27--step-10) |

Use the current headless SUMO validator as the traffic baseline. A live fused baseline needs CARLA on Town10HD_Opt, separate output folders, and repeatable short runs spanning the four radar counts. Compare by frame offsets within each run because CARLA global frame numbers and actor IDs can vary across sessions.
